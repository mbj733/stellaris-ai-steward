# 战略审计（2026-10-17 实机存档）

> 数据源：最新自动存档 + `war_audit.py` / `strategy_audit.py`。  
> 原则：先看数，再下结论；不确定的地方明确标"未接管"。

## 结论摘要

1. **当前战争已经赢了，不是战争组件打赢的。**  
   我方阵营军力约 **1.93M**，敌方约 **2.3k**；战争疲劳 **0.18 vs 8.08**（敌方接近崩溃）。
   战争组件的作用是保持 `aggressive`、同星系接敌、增援/推进，属于"收尾与防意外"，不是胜负主因。
2. **战争组件原版会浪费弱舰队。** v0.4 已改为：
   - `fleet_power < 5000`：`evasive` + 弱舰队标记，不主动追击/推进；
   - `fleet_power >= 5000`：才参与 `auto_follow_fleet` 和增援/进攻；
   - 和平期清除弱舰队标记。
3. **科研不是最优。** 游戏 AI 当前研究：
   - 物理：聚焦阵列，评分排名 **3/5**；
   - 社会：神经抑制器，排名 **3/5**；
   - 工程：改进泰坦船体，排名 **2/6**，审计建议 **暗物质推进**（7.9 vs 7.3）。
4. **传统有未完成树。** 已 adopt 7 棵树，`和谐` 未 finish；完成奖励通常强于再开一棵。
5. **政策适合战争。** 战争哲学=无限制战争、轰炸=选择性、AI=公民权、外交=乐于合作；
   不需要为了这场战争改政策。
6. **经济健康，但不能自动切军事经济。** 月度净收入：
   - 能量 +25（偏薄）、矿物 +72、食物 +245、合金 **+340**、消费品 **+40**；
   - 军事经济会 `-25%` 消费品产出，当前 +40 的安全垫不够，可能直接转负。
   **因此不要自动切 `economic_policy_military`**，除非消费品净收入 > 300。

## 自动化边界（重要）

| 领域 | 当前由谁决策 | 本工具是否接管 |
|---|---|---|
| 事件选项 | 本工具（`evt_decide` + 探测天梯） | ✅ 已接管 |
| 战争姿态/接敌/增援 | 本工具战争组件（v0.4） | ✅ 部分接管 |
| 科研选择 | 游戏内置 AI | ❌ 只审计/建议 |
| 传统选择 | 游戏内置 AI | ❌ 只审计/建议 |
| 政策/经济 | 游戏内置 AI + 玩家 | ❌ 只审计/建议 |
| 建造/扩张/舰队编成 | 游戏内置 AI | ❌ 未接管 |
| 外交/宣战/和平 | 游戏内置 AI + 玩家 | ❌ 未接管（高风险） |

结论：**"托管"仍以游戏 AI 为执行底座**；本工具目前是"事件决策 + 战争战术 + 监督审计"，
不是完整的战略 AI。要真正做到"不依赖内置 AI"，下一阶段需要打通科研/传统/建造的
写入通道（内存或 UI 自动化），这是独立的大工程。

## 立即可用的命令

```bat
python tools\war_audit.py        :: 双方军力/疲劳/局部兵力/集中度 + 建议
python tools\strategy_audit.py   :: 科研/传统/政策/经济/战争全面审计
python tools\war_mode.py audit   :: 战争参谋（只读）
python tools\war_mode.py auto    :: 按参谋建议切进攻/防御（敌军崩溃时不自动推进）
```

## 下一步建议（按收益排序）

1. **科研队列接管**：优先做"读取当前研究 + 改写队列"的内存通道；这是长期收益最大的一项。
2. **传统收尾**：先让 AI/玩家把未完成树收掉，再开新树。
3. **战争经济开关**：只在消费品净收入 > 300 时允许自动切军事经济。
4. **舰队编成顾问**：按敌方舰船设计推荐我方武器/护盾配比（需要解析 ship_design）。
5. **和平/战争目标顾问**：按战争疲劳与占领进度建议"继续/现状和平/割地"。
